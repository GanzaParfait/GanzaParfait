Yes. I would change this before running it.

The current record unintentionally reduces LERONY Ltd to a software-development/consulting company. Phrases such as “commercial home for custom software”, “commercial vehicle for software, systems, and consulting work”, and especially "category": "saas" make software look like Lerony's identity rather than one part of a broader technology and innovation company.

Based on how you've been positioning Lerony, I would make the company-level definition broader and let individual projects demonstrate the software-development capability.

What I would change

The biggest issue is this:

"category": "saas"

LERONY itself is not a SaaS product. Use something like "technology" or "company" if your codebase supports it.

The second issue is the hierarchy. Right now it effectively says:

LERONY → Software → Web → Business systems → AI → Consulting

I would position it more like:

LERONY → Technology & Innovation → Digital Solutions + Smart Systems + Business Transformation + Technology Strategy + Software/Platforms + Emerging Technologies

Software remains important, but it becomes an execution capability, not the entire identity.

I would also avoid defining Lerony by today's tech stack:

"technologies": ["Next.js", "TypeScript", "React", "Node.js", "Supabase"]

Those technologies may describe lerony.com, but not LERONY Ltd. A company isn't React + Supabase. If this field must exist because of your project schema, either use broader capability labels or distinguish websiteTechnologies from company capabilities.

Stronger LERONY master definition

I would make the canonical definition something close to:

LERONY Ltd is a Rwanda-based technology and innovation company that helps organizations, businesses, and communities use technology to solve real problems, improve operations, create new opportunities, and build for the future. The company works across digital solutions, smart systems, technology strategy, business transformation, software and platforms, AI-enabled solutions, and emerging technologies. Rather than being defined by a single technology or service category, LERONY focuses on understanding problems and applying the right combination of technology, innovation, people, and strategy to create practical and scalable solutions.

That gives you room in the future for things that aren't traditional software projects.

One important wording choice: I wouldn't add a huge catalogue like blockchain, IoT, robotics, cybersecurity, cloud, data science, etc. unless Lerony actually offers or is actively developing those capabilities. Saying “emerging technologies” preserves the broader ambition without inventing current capabilities.

More importantly: don't fix only this SQL record

Your concern about changing it globally across the codebase and Supabase is correct. Otherwise you'll fix this record while the homepage, SEO metadata, structured data, About content, project filters, admin defaults, database seeds, or hard-coded fallback copy may still call Lerony a “software company.”

And there's one technical correction in your SQL: this:

"links": { "live": "[https://lerony.com](https://lerony.com)" }

should almost certainly be:

"links": { "live": "https://lerony.com" }

The current value stores Markdown syntax inside the URL field, which can break buttons/navigation depending on how the frontend consumes it.
