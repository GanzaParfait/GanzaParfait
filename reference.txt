Yes. That can work very well for your personal-brand site, especially because the rest of the site is already becoming information-rich. I’d treat it as a very short multilingual opening sequence, not a traditional loading screen.

Your reference is extremely minimal: dark full-screen background, one greeting at a time, then the actual site appears. For yours, I’d keep that simplicity but make it recognizable as Prince Parfait GANZA.

Recommended experience

When someone enters princeparfait.com for the first time:

Full screen
────────────────────────────

              Hello.

────────────────────────────

Then the same position transitions through configured greetings:

Hello.
→ Bonjour.
→ Muraho.
→ مرحباً.
→ Hallo.
→ Hola.

Then the last greeting fades/moves away and the homepage reveals underneath.

I wouldn't put your logo, name, loading percentage, social icons, or “Welcome to my portfolio” on this screen. The simplicity is what makes this type of opening feel premium.

Also keep the whole thing short—around 1.8–2.5 seconds total, rather than showing every configured language for several seconds. If you eventually configure 15 languages, the system shouldn't force visitors to watch all 15; the dashboard should let you control how many greetings participate in one opening sequence.

Make it completely dashboard-controlled

This is the important part. Don't hard-code Hello → Bonjour → Muraho.

Drag-and-drop should control order. Each greeting needs only text, language/locale, enabled, and position/order. You can add "Ciao", "Olá", "Jambo", or anything else later without touching code.

For Arabic and other RTL languages, the intro should automatically support the correct text direction.

One improvement over the reference

Don't make it an actual dependency for loading the application. Your homepage should already be loading behind it.

Conceptually:

site loads → intro overlay appears → greetings animate → overlay reveals already-rendered homepage

rather than:

intro loads → wait → fetch website → render homepage

That distinction will make it feel much faster.

I would also configure first visit only as the default. Seeing it once feels like a brand moment; seeing it every time someone clicks Home can quickly become annoying. You can remember dismissal locally, while still having a dashboard option for once-per-session or every visit.

And respect prefers-reduced-motion: those visitors should get either a simple short fade or no intro.
